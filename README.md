# 内容工作台 · 小红书图文（第一屏）

游戏截图 → 视觉模型识别 → 5 套小红书图文（标题 / 正文 / 标签 / 卡片大纲）。

## 跑起来

```bash
cd xiaohongshu
npm install
npm run dev          # http://127.0.0.1:5173
```

只需要一个进程：模型调用挂在 Vite 中间件里，不用另外起后端，也不用配代理。

### 手机端访问

默认监听局域网，**手机连同一个 WiFi** 打开启动日志里的 Network 地址（如 `http://192.168.42.113:5173`）即可，识别 / 生成 / 出图全部可用。只想本机访问时在 `.env` 写 `EXPOSE_LAN=0`。

## 接模型

项目已配好可用的 Key，**开箱即用**。若要改，编辑 `.env`（OpenAI 兼容的 `/chat/completions` 接口即可）：

```env
VISION_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
VISION_API_KEY=...

# 最低成本组合（详见下方「当前配置」）
VISION_MODEL=qwen3.5-omni-flash   # 视觉：唯一还能调的
TEXT_MODEL=qwen-flash             # 文案：0.15/1.5，最便宜一档

# 出图（阿里云通义万相，异步任务制）
IMAGE_MODEL=wanx2.1-t2i-turbo
IMAGE_SIZE=720*1280
IMAGE_FALLBACK=1   # 出图失败时降级为本地渐变底图

# 视频（通义万相视频生成，异步任务制，20s ~ 2min）
VIDEO_MODEL=wanx2.1-t2v-turbo
```

界面右上角 **⚙️ 模型设置** 也能改 base / key / 视觉模型 / 文本模型，点「测试视觉模型」「测试文本模型」可当场验证连通性，保存在浏览器本地，**不用重启服务**。留空则回落到 `.env`。

| 服务商 | VISION_API_BASE | 推荐的 VISION_MODEL |
| --- | --- | --- |
| 阿里云百炼（现用） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3.5-omni-flash` / `qwen3-vl-flash` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4v-flash` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-VL-72B-Instruct` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o` |

**Key 留空时接口返回模拟数据**，界面照常能跑通，方便先看交互。

### 当前配置：最低成本组合（2026-09 实测）

逐个模型实测过当前 Key 的可调用性后选定的组合：

| 链路 | 模型 | 单价 | 为什么选它 |
| --- | --- | --- | --- |
| 截图识别 | `qwen3.5-omni-flash` | 2.2 入 / 13.3 出（元/百万 token） | **视觉侧没得选** —— 所有专职视觉模型都额度耗尽了，只有它还能调 |
| 文案生成 | `qwen-flash` | **0.15 入 / 1.5 出** | 最便宜一档。比 omni-flash 输入便宜 15 倍、**输出便宜 9 倍**，而文案正是输出 token 大户 |
| AI 出图 | `wanx2.1-t2i-turbo` | ~0.16 元/张 | 出图候选里最便宜，且比 `qwen-image-plus` 只慢 3 秒 |
| 生成视频 | `wanx2.1-t2v-turbo` | 按秒计 | 单次开销最大 |

跑了一次完整流程的**成本结构**（重点）：

| 环节 | 单次成本 | 占比 |
| --- | --- | --- |
| 识别 1~6 张截图 | ~0.003 元 | <1% |
| 生成 5 套文案 | ~0.003 元 | <1% |
| **出图 5 页** | **~0.8 元** | **95%+** |
| 生成 1 条视频 | ~1~2 元 | 单次最贵 |

**结论：省钱的关键不在模型选型，在少出图。** 文本和视觉加起来不到一分钱，出图才是大头。想省就从这几处下手：

1. 卡片大纲控制在 4 页以内（少一页省 ~0.16 元）
2. 复用已生成的配图，别反复「重新出图」
3. 想零成本预览 → 设置 `IMAGE_FALLBACK=1`，出图失败会自动用本地渐变底图
4. 视频最贵，确定要发再生成

### 额度状态与排错

百炼的可用性是**波动的**：同一批模型昨天可能全 400、今天全通，单次失败不构成结论。三种报错要区分：

| 报错 | 含义 | 怎么处理 |
| --- | --- | --- |
| `Access denied, account is in good standing` | 账户欠费 | 充值，或换 `qwen3.5-omni-flash` / `qwen-flash` |
| `Free quota exhausted` | 该模型免费额度用完，且未走付费 | 充值，或换还有额度的模型 |
| `The model xxx does not exist` | 模型名错 / 没上架 | 换模型名 |

改完 Key 或模型拿不准时，先跑 `node tools/probe-models.mjs` —— 它会带单价把文本/视觉/出图三条线的候选全测一遍，再照着结果填 `.env`，别凭记忆猜。

各线曾实测过的替代（`node tools/probe-models.mjs` 会重新验一遍）：

- 视觉：`qwen3-vl-flash`（0.15/1.5，理想替代，需先解冻额度）、`qwen-vl-ocr`（0.3/0.5，专职 OCR）
- 文本：`qwen-turbo`（0.8/2.0）
- 出图：`qwen-image-plus`（0.2 元/张，比万相快 25%）、`qwen-image-max`（0.5 元/张，画质最好）

第三方更便宜的选项（需各自注册拿 Key）：智谱 `GLM-4.7-Flash`（视觉，免费日限 100 万 token）、DeepSeek `V4-Flash-Vision-Exp`（单图 ≤384 token，约 0.001 元/张）、硅基流动 `Z-Image-Turbo`（0.1 元/张）。

**Key 留空时接口返回模拟数据**，界面照常能跑通，方便先看交互。

### 免费小模型的已知毛病，代码里已经兜住

1. **偶尔吐出畸形 JSON**（`bullets` 该是数组却写成字符串）→ `normalizeCandidates()` 会掰正类型，解析失败还会自动换温度重试 3 次。
2. **正文容易偷懒写短** → 提示词里把字数当硬指标，并在输出长度上取实测稳定的 4096。`qwen-flash` 在 300 字档实际写 230~270 字，要更长正文请调 UI 的字数档位或换回 omni-flash。

### 事实性约束（防编造）+ 联网检索核验

模型本身不联网，"参考真实文章"以前只能靠它自己的记忆。所以现在加了一步**真实检索**：

```
识别到游戏名（gameName） → 服务端联网检索 → 结果作为「事实依据」注入生成提示词
```

**检索链路**（`server/api.mjs` 的 `researchGame()`，接口 `POST /api/research`）：

1. 识别结果里多了 `gameName` / `platform` 两个字段，由视觉模型从截图标题 / Logo 里认；认不出写"未知"。
2. 用游戏名拼 3 条查询：`"<game> 官方 游戏介绍"`、`"<game> 玩法 机制 评测"`、`"<game> 攻略 wiki"`，服务端逐条抓取。
3. 结果去重、过滤词典 / 汉字解释页等噪声，最多保留 8 条（官网 / 百科 / 评测媒体），整理成带 `来源N：标题 / 链接 / 摘要` 结构的 `facts` 段落。
4. 生成时把 `facts` 插在【识别结果】之后，作为**最高优先级事实依据**，优先级高于截图证据、高于模型记忆。

**UI 怎么用**：识别完成后会出现「🔍 联网核验资料」按钮，点了可以查看实际抓到了哪些来源（每个都可点开原链接自查）。直接点「生成小红书图文」时会自动先跑一次检索（检索失败不影响生成，会降级为仅依赖截图证据）。核验过的卡片上会带「✓ 已联网核验」角标。

**搜索后端**（都免 API Key）：

- 默认 **Bing 网页版抓解析**（`bingSearch()`），实测能拿到官网、百科、媒体的真实标题+摘要+链接。**已验证可用**。
- 可选升级：`.env` 里配 `RESEARCH_TAVILY_KEY=<Tavily API Key>` 后自动切到 Tavily（返回更干净、带正文，适合长期用；免费额度 1000 次/月）。配了就生效，不用改代码。

> 曾经试过的路子（都因为本机/网络限制放弃，别再踩）：DuckDuckGo HTML（沙箱 `fetch failed`）、jina.ai Reader（`fetch failed`）、直接抓官网正文（原神官网是 JS 渲染，只有 meta 标题可用）、百度百科（403 反爬）。**页正文抓取基本拿不到东西，搜索结果的「摘要」才是最划算的事实源**。

提示词里的约束仍然是硬性规则：禁止编造游戏名 / 角色名 / 活动名、数值、版本时间、玩法机制、剧情设定、联动信息；来源查不到出处的细节必须改写成不含具体数字和专有名词的泛化表达（写"前期资源紧张"而不是"开局只有 120 体力"），**宁可写得空，不可写错**。

要调整约束或查询词，改 `server/api.mjs` 的 `generatePrompt()` 和 `researchGame()`。

## 使用流程

1. 拖入 / 点选 / **Ctrl+V 粘贴** 1-6 张游戏截图，左侧可预览、切换、删除（粘贴为全局监听，页面上任意位置 Ctrl+V 都行；上传前自动压缩到长边 1280px）
2. 右侧调语气、受众、字数（可选填识别关注点和额外要求）
3. 点「识别截图」→ 展示 **游戏玩法 / 视觉风格 / 引用证据**（证据字段强制要求来自截图可见内容，看不清就写"未识别"）
4. 可点「🔍 联网核验资料」看这个游戏抓到了哪些真实来源（也可跳过，生成时会自动跑）
5. 点「✨ 生成小红书图文」→ 5 个不同角度的方案，每张卡可单独复制标题 / 正文 / 全文
6. 每张卡点「🎨 生成配图」→ 按卡片大纲**逐页 AI 出图**（默认最多 4 页），边生成边能在预览里看到，可单张或全部下载 PNG
7. 每张卡点「🖼️ 导出成品图」→ 把标题 / 要点合成到配图上，导出 1080×1440 成品 PNG（可调版式、字号、字色、蒙层、行距、水印），支持导出当前页或全部页
8. 点「📱 小红书预览」→ 手机端效果：3:4 封面图 + 标题压字，左右箭头按卡片大纲逐页切换 banners，下方是作者栏、标题、正文、蓝色话题标签，底部有点赞 / 收藏 / 评论数（模拟数据）

> 预览的封面默认用你上传的截图占位，点了「生成配图」后换成 AI 生成的成品图。

### 导出成品图

- AI 配图刻意不含任何文字（模型画出来的字基本是坏的），标题全部由这步用 Canvas 叠加，**到这里才形成闭环**
- 导出页数 = **封面 + 每一页大纲**。封面用你选的截图，大纲第 k 页用第 k 张 AI 配图（没出图则回落到截图）
- 三种版式：底部压字 / 居中大字 / 顶部色条；可调字号(48-140)、行距、字色(白/黑)、蒙层深浅、是否显示要点与页码、署名水印
- 画布 1080×1440（3:4），导出走 **Blob URL** 而非 dataUrl —— iOS Safari 对超大 dataUrl 的 `<a download>` 会静默失败
- 排版参数存在 localStorage，下次打开沿用

### 出图说明

- 走阿里云**通义万相**（异步任务：提交任务 → 轮询 → 取图），每张约 12-15 秒
- 提示词由识别结果自动生成：美术风格 + 氛围 + **取色 + 该页大纲要点 + 游戏类型**，并强制"画面中不出现任何文字"（AI 生成的字基本是坏的，标题留给你后期叠加）
- 默认竖版 `720*1280`（接近小红书 3:4）；若所选尺寸不被支持会自动退回 `1024*1024`
- 服务端会把图片拉回来转 DataURL 再返回，避免 OSS 直链过期（通常几小时）和跨域问题，同时能直接下载
- 出图额度与大模型额度是分开的，大语言模型 403 不代表出图不能用

| 服务商 | 出图接口 | 推荐模型 |
| --- | --- | --- |
| 阿里云通义万相 | `https://dashscope.aliyuncs.com/api/v1/services/aigc/text2image/image-synthesis` | `wanx2.1-t2i-turbo` / `wanx2.0-t2i-turbo` |

### 生成视频

- 每张卡点「🎬 生成视频」，两种方式：
  - **图生视频**：让现有画面动起来，画面主体不变，出片最稳。底图可选封面截图 / 该页 AI 配图 / **合成成品图（带标题）** —— 选合成成品图出来就是能直接发的带字竖版视频
  - **文生视频**：画面完全由提示词生成（自动带上视觉风格 / 取色 / 大纲要点），适合还没出配图时先出个片
- 可选镜头运动（缓慢推进 / 拉远 / 环绕平移 / 主体微动 / 光影流动）、画质档位（turbo 快 / plus 精细）、分辨率与提示词（自动生成，可改）
- 视频是**异步任务**（turbo 约 20s~2min，plus 约 1-2min，底图未压缩时更慢），对话框里实时显示已等待秒数，可中途停止；生成后视频存在卡片上（「▶️ 看视频」），不用怕关掉弹窗丢失
- 送进视频接口的底图会先压到 720px —— 原图过大时提交能慢到 5 分钟，压缩后正常
- 播放与下载都走服务端代理 `/api/video-proxy`（带 Range 支持可拖进度条），因为 OSS 直链会过期且可能跨域；代理只放行 `*.aliyuncs.com`，防 SSRF
- 模型名不用手填：按「图生/文生 + 画质」从 `VIDEO_MODEL` 自动推导（如 `wanx2.1-t2v-plus` → 图生视频自动变 `wanx2.1-i2v-plus`）

| 服务商 | 视频接口 | 推荐模型 |
| --- | --- | --- |
| 阿里云通义万相 | `https://dashscope.aliyuncs.com/api/v1/services/aigc/video-generation/video-synthesis` | `wanx2.1-t2v-turbo` / `wanx2.1-i2v-turbo`（plus 更精细更慢） |

## 实测结果（已跑通）

用 FGO 的宣传图做了端到端验证：

- 识别 5.1s：正确识别出「卡牌构筑 / 策略角色扮演」「英灵召唤」「指令卡选择战斗」，取色 `#F5CBA7 / #D8A0B1 / #8B1538`，引用证据准确抓到画面中的 `Fate/Grand Order` Logo 与日文副标题，置信度 0.95
- 生成 13.7s：5 套方案分别为美术赏析 / 历史神话种草 / 新手避坑 / 情感共鸣 / 社交互动，每套 6 个标签 + 4 页卡片大纲
- 多图（3 张）识别 3.8s 正常返回

## 注意

- **视频/出图/文本整号报 `Access denied ... overdue-payment` 时是阿里云账户欠费**，充值恢复后功能即刻可用（实测恢复前已跑通视频全链路）
- 截图上传前压缩到长边 1280px，避免请求体过大
- `server/api.mjs` 只适合本地开发；要部署上线需把它挪到正式的 Node / Python 服务里
- 接口失败时返回 200 + `{ ok:false, error }`，前端统一在底部红条提示
- 视觉模型对纯宣传图/过场动画能识别美术与文字，但看不到实际玩法 UI 时会在 `notes` 里说明 —— 想让玩法识别更准，优先传主界面、战斗界面、养成界面这类截图

## 双端适配

- **桌面端（>700px）**：左右双栏，卡片内生成按钮
- **手机端（≤700px）**：单列流式布局；底部固定主操作条跟着流程走（上传 → 识别 → 生成）；候选卡操作按钮横向滑动；证据表格横向滚动；模型设置变为底部抽屉；表单字号 16px 防 iOS 聚焦缩放；适配刘海屏安全区（`safe-area-inset`）
- 手机上「拖拽」和「Ctrl+V」不适用，相关提示会自动隐藏，直接点上传区即可（支持多选 / 拍照）
